二、核心功能包（自研）

quad_utils

  • **功能**：基础工具库，几乎所有包都依赖它。
  • **节点 / 关键模块**：
    • QuadKD：运动学 / 动力学求解
    • rviz_interface_node：RViz 可视化接口
    • terrain_map_publisher_node：地形图发布
    • trajectory_publisher_node：轨迹发布
    • remote_heartbeat_node：远程心跳
    • mesh → grid map 转换、数学 / ROS 工具
    • 顶层 launch：quad_gazebo.launch、quad_plan.launch
  • **说明**：属于「底层工具」，不直接参与控制，但为其余包提供运动学、可视化与启动编排支撑。

quad_msgs

  • **功能**：自定义 ROS 消息 / 服务类型，是各模块之间通信的**数据契约**。
  • **节点 / 关键模块**：消息类型如 LegCommandArray、LegState、RobotState 等。
  • **说明**：无节点，纯消息定义包；其余包均依赖它来完成话题通信。

robot_driver

  • **功能**：机器人驱动层，把上层下发的腿命令解算为关节指令，并向上反馈机器人状态。
  • **节点 / 关键模块**（节点名 robot_driver）：
    • 状态估计 estimators/：ekf_estimator、comp_filter_estimator、state_estimator
    • 腿 / 关节控制 controllers/：grf_pid_controller、inverse_dynamics_controller、joint_controller、leg_controller
    • 硬件 / 仿真接口 hardware_interfaces/：spirit_interface（走 mblink 通信）、hardware_interface
  • **说明**：属于「执行与感知闭环」的核心，连接控制层与真实硬件 / 仿真。

global_body_planner

  • **功能**：全局运动规划器，在 grid map 上做**全局身体轨迹规划**，生成跳跃 / 奔跑等动态机动的离散身体动作。
  • **节点 / 关键模块**（节点名 global_body_planner）：rrt.cpp、graph_class、planner_class、gbpl、global_body_plan。
  • **说明**：基于 RRT / 图搜索；输出供 local_planner 细化，不直接控制关节。

local_planner

  • 功能**：局部规划器，接收 twist 输入或全局规划结果，做身体规划、脚步规划、步态生成与腿轨迹规划，并最终输出 LegCommandArray。
  • **节点 / 关键模块**（节点名 local_planner_node）：local_footstep_planner，并**调用 nmpc_controller 做轨迹优化。
  • **说明**：介于规划与执行之间的枢纽，把高层目标转成可执行腿命令。

nmpc_controller

  • **功能**：非线性模型预测控制（NMPC）求解器，生成并优化关节 / 脚掌轨迹。
  • **节点 / 关键模块**：以库形式提供 —— quad_nlp、quad_mpc、quad_sqrt、spirit_interface。
  • **说明**：被 local_planner 调用，不独立运行节点。

quad_logger

  • **功能**：数据记录与后处理工具。
  • **节点 / 关键模块**：基于 rosbag2 记录 / 回放（bags/、logs/）；附带 MATLAB（<tt>.m

）和 Python（<tt>.py）分析脚本用于离线可视化。

  • **说明**：用于实验数据留存与离线分析，不影响实时控制。

三、仿真与机器人描述

位于 quad_simulator/ 目录。

包名 功能
spirit_description Ghost Robotics Spirit 40 机器人的 URDF、meshes 与材质描述（硬件本体定义）。
a1_description Unitree A1 四足机器人的 URDF 描述（另一支持平台）。
gazebo_scripts Gazebo 仿真脚本与控制器插件（spirit_controller_plugin），在仿真中模拟机器人动力学与控制接口。
